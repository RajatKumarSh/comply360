# ADR-010: Identifiers, Tenancy and Time

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-09-27 |

## Context

Architecture v0.1 preferred UUID primary keys with separate human-readable identifiers, and suggested `organization_id` for future multi-tenancy. Business calculations (days elapsed, due dates, overdue status) need a defined time zone.

## Decision

### Identifiers

- Primary keys are UUIDs generated with `gen_random_uuid()`.
- Workshops have a separate human-readable **workshop code** (for example `W-000123`), unique per organization and generated by a database sequence.
- Other human-readable codes may be introduced per entity where useful.

### Tenancy

- `organization_id` is included on top-level tables (organization-owned master data, configuration, workshops).
- Workshop-owned child tables inherit organization through their workshop.
- V1 operates a single organization. There is no tenant-switching UI.

### Time

- All timestamps are stored as `timestamptz`.
- Business-date calculations use the organization's time zone setting. Initial value: `Asia/Kolkata`.

## Consequences

- Internal IDs are non-sequential and integration-friendly.
- Users work with readable workshop codes.
- Future multi-company support is possible without re-keying.
- Date-based calculations are consistent regardless of server time zone.

## Deferred / Open

- Exact workshop code format.
